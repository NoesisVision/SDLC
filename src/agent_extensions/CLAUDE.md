# Skills guidelines

## General

1. Agents read data via the Read tool. Scripts AND MCP tools that may return more than ~10 KB of content (or any knowledge payload that can grow with project size — topic listings, topic details with long summaries, enriched topic dumps, transcript chunks) MUST write the result to a tmp file and return only a short JSON message containing the file path. The agent then reads the file with the Read tool. This avoids stdio/MCP transport limits and keeps the agent's context clean.
2. Scripts and mcp tools should produce Markdown and accept JSON. Structure data as tool's input, compact and easy to read Markdown as an output consumed by agent.
3. Tools that return small status/confirmation payloads (e.g. `{ id, added: 2 }`) return them inline as JSON — the file pattern applies only to potentially large content.
4. If agent add data to mcp server the server is responsible for validating the input and returning errors. Agent must fix errors and add corrected data once again. Do not validate data in scripts outside mcp server in such cases.

## TypeScript scripts (Bun)

1. All scripts run with `bun run scripts/<domain>/<script>.ts`.
2. Scripts are organized by domain, not technical pattern. Do NOT create directories based on code role (e.g. `types/`, `utils/`, `helpers/`). All code related to a domain concept — types, schemas, scripts — lives together in that domain's directory.
3. All JSON generated by AI agents must be validated with Zod schemas. On validation failure, write the Zod error message to stderr and exit with code 1.
4. Success: exit code `0`, result JSON to `stdout`. Error: exit code `1`, error message to `stderr`.
5. Every public function and every script must have tests. Use `bun test` with colocated `.test.ts` files.
6. Guard script entry points with `if (import.meta.main)` so modules can be imported in tests without side effects.
