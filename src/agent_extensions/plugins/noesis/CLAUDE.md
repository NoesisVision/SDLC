# Noesis plugin guidelines

## TypeScript scripts

1. All scripts run with `bun run scripts/<domain>/<script>.ts`.
2. Scripts are organized by domain, not technical pattern. Do NOT create directories based on code role (e.g. `types/`, `utils/`, `helpers/`). All code related to a domain concept — types, schemas, scripts — lives together in that domain's directory:
   ```
   scripts/
   ├── transcript/       # parsing, structuring, chunking
   ├── conversation/     # init, chunk results, topic assignments
   ├── topics/           # listing, review, potential topics, decisions
   └── knowledge-graph/  # init, merge, listing
   ```
3. All JSON generated by AI agents must be validated with Zod schemas. On validation failure, write the Zod error message to stderr and exit with code 1.
4. Strong types everywhere — `any` is not allowed.
5. Success: exit code `0`, result JSON to `stdout`.
6. Error: exit code `1`, error message to `stderr`.
7. Agents read files via the Read tool. If only part of a file is needed, the script filters relevant content and writes it to a tmp file for the agent to read.
8. Every public function and every script must have tests. Tests verify requirements and expected behavior, not implementation details. Use `bun test` with colocated `.test.ts` files.
9. Guard script entry points with `if (import.meta.main)` so modules can be imported in tests without side effects.

## Naming conventions

- **Files and directories:** `kebab-case` (e.g. `save-chunk-result.ts`, `knowledge-graph/`)
- **Types, Interfaces, Enums, Zod schemas:** `PascalCase` (e.g. `ConversationSchema`, `IdeaUnitCategory`)
- **Functions, methods, variables:** `camelCase` (e.g. `loadTopicForReview`, `turnMap`)
- **Constants:** `UPPER_SNAKE_CASE` (e.g. `DEFAULT_TOKEN_LIMIT`, `CHARS_PER_TOKEN`)
